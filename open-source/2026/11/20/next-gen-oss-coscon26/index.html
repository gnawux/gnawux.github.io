AI Coding 之后：探索开源技术的下一代

gnawux cosconsbomcommunityspeechopen-source

本文是2026年11月14日的 COSCon （中国开源年会）的早场主题演讲的大纲成文稿，感谢 Emily 和 Richard 的邀请，由我来呼应这次大会的主题「开源下一代」而做此演讲。全文手工写作，处处提及 Agent，本文却并无 AI 参与写作。

作为玩开源20多年、从事开源相关工作快20年、10年前开始开源创业、和开源基金会过从甚密快10年，又执掌企业开源3年的老登，我自知自己绝对是“开源上一代”，对于下一代，只敢略作揣测，绝不敢断言，这里浅谈一些自己的观察和思考，抛砖引玉。

01

我想在一开始先回顾一下曾经我所认识的开源，我们的目的是讨论 AI Coding 对开源的巨大冲击，但是我想要强调的是，即使在过去的40年里，开源的主线也并非 Coding——

首先，开源它是一个创新的基础平台、一个“可以让更多普通人站上去的肩膀”，这个立意出自于 Richard Stallman 的自由软件运动的核心追求——软件是人类的精神财富，不应该封闭起来，应该让人可以阅读、学习、并做出更好的软件。在我的职业生涯早期，参与过的第一个重要开源项目就是 Apache Hadoop，这个项目的设计本身并非完全的创新，它从实现 Google 的 GFS, MapReduce 等论文开始，然而，之后一整个「大数据时代」的开源生态，无疑都直接或间接地继承了 Hadoop 家族的遗产，可以说它是”肩膀“的典型代表。

其次，开源的一个重要社会价值是加速先进理念的传播，过去10年间的最具影响力的开源项目可能要数云原生生态的核心 Kubernetes 了，提到 K8s，大家一定会把首功记在 Google 身上，然而，如今的 K8s 的贡献者中 Google 的代码本身并非绝对多数，但是它的影响力体现在它引入并推动了基础设施代码化、不可变基础设施、声明式 API 这些云原生的架构范式，让这些先进理念得以迅速普及，也构建了自己的影响力壁垒。

最后，开源还是团结不同利益群体的纽带。以和我关系密切的 OpenStack Foundation （现在的 OpenInfra Foundation (OIF)）为例，这个基金会的旗舰项目 OpenStack，早已成为了一套用代码写成的私有部署基础设施云服务的标准，使得不同的 IT 设备厂商和集成商可以提供接口一致的私有云等基础设施产品，解耦了云应用和基础设施产品的研发和销售，让这些不同的利益群体可以共同在开源社区协作、再在市场上提供可复操作的产品，从而让客户在采购时不必担心厂商锁定问题。

所以，开源本来就不只是代码。

02

其实在过去的两年里，我们蚂蚁开源也在尝试发掘开源在代码之外的价值，其中一个很有意思的工作就是蚂蚁开源的基于 GitHub 的开放数据做的趋势分析（和华师大 XLab 合作的），我对这个项目的定位是——新时代的技术趋势报告，不一定像 Gartner 那样来自问卷、调研和市场，也可能来自对开源社区的行为和互动数据的洞察。这个 Agent 生态全景图相关的内容我们在很多文章里都提过，就不在本文赘述了，我只是说一点和我们今天的主题相关的观察：

在过去的一年中，开源项目和开源贡献者经历了双重的暴增，这无疑既反映了 Agentic 带来的热潮，也得益于 Agentic Coding 带来的代码生产效率的显著提升。但是从另一面看，PR 与 Issue 的比例的上升与 PR 被成功关闭的效率的下降也在同时发生着，这也反映了我们大家都体会到的非常一致——大量的 PR 都包含了 Agent 生成的内容，然而，Review 这些 PR 是一件相当棘手的事情，一方面是 PR 的数量多了，但很多 PR 的提出者都是这些项目的“新人”，另一方面是 Agent 也倾向于生成更冗长的内容，于是很多项目维护者都开始为 Agentic Coding 的贡献设立不同高度的门槛。用我的话说就是——没理由让我的维护者用他们宝贵的人类的时间来 Review 海量的机器生成的代码。

03

我是从盐湖城 KubeCon 用 26 小时的转场，直接飞到杭州来做这次 COSCon 的 Keynote 的。在之前几天的 KubeCon 上和很多老朋友交换了很多看法，这次的表达除了过去的积累之外，也有一些战地记者报道的味道。

这次 KubeCon 的主题基本上是 Agent，安全，以及 Agent 与安全；我们在 CNCF GB 和 TAB 的战略会的分组讨论里聊到的当前的“GAP”时的一个点就是“信任（Trust）”——对于使用 Agent 生成的贡献代码，我们很难秉承对老开发者那样的信任来 Review 并接受代码的，我不知道这些代码里有多少幻觉，不知道提交代码的贡献者是否仔细看了并理解了每一行代码，不知道生成代码的 Agent 是否有被人恶意投毒，甚至都不能忽略这个提交者在冗长代码之中故意插入了恶意代码的可能性。

同时，Agent 帮助很多没有仔细设计、审慎评估的潜在 0-day 漏洞都能顺利上线并暴露在公网上，另一些 Agent 又帮助本不强大的攻击者获得了高阶攻击能力。这让开源代码的安全风险已经达到了40多年以来的最高点，并且还可能更高。

这一切问题的一个根源，大概可以做这么一个类比——我们把 Agent Coding 的引入看作是一台 10 倍动力的发动机，当我们把这台发动机固定到一辆老车上，却没有相应地加强底盘、悬挂、轮胎、制动、结构、乃至空气动力等各个方面的时候，就期待这台车可以直接提速到原来的10倍，但现实却可能是启动直接解体，而当我们相应地改造了所有相关系统，甚至是做一些结构调整之后，我们可能发现它甚至没有提速到两倍。

在主题演讲之后的当晚，我遇到了 OpenChain 的 ED Mary，两个疲惫的人又长谈了一个小时，我们把这个话题拓展到了软件开发周期中的可信，或者说是 Agent Coding 已经是软件开发中的一个复杂过程，却尚未纳入软件供应链的管理（SBOM）之中，在 SBOM 中明确包含生成代码所需的自然语言和相应的并有一定确定性的 Agentic Coding 过程，将是当下的一个需要解决的课题。

换句话说，我们现在仍然在一个适应的过程之中，我们正在探寻开源技术的下一代，本来大会主席 Richard 给我的命题里是不带“探索”这个动词的，但我想，「下一代」的时态仍然是「未完成时」（imperfect）的，加上“探索”这个动词会更合理，也让我略有一点配得感。

04

不论如何，我们都知道这个事实已经不可逆转——越来越少的人会从头到尾手写源代码，正如很多年前，我们就开始放弃了从头到尾手写汇编代码；在未来，能读懂并少量编写/修改关键代码的人将是特殊人才，而远多于当下的专业软件工程师（程序员）的人都可以使用计算机完成更复杂的工作了。

而在这个背景下，我们不拘泥于「源代码」这个概念，而回到开源的第一性，回到“自由软件”，也回到我开头所说的，就是要开放「我如何构建软件」这个过程，让后人可以踩上前人的肩膀，而不止是阅读作为开发的中间产品的源代码——换句话说，（有严谨逻辑的）自然语言正在成为「新的源代码」。

而下一代开源社区，仍然是也应该是那个催化创新、扩散技术理念、推动协作的人类的社区，只是建立在新的基础之上。
